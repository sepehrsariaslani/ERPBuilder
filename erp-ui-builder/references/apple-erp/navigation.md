# Navigation

Use the business mental model for routes and labels, while retaining existing route contracts: for example order → production → delivery → payment. Always show current location and a predictable way back. Use breadcrumbs for document depth, tabs for stable peer sections, and contextual panels for drill-down. Tabs navigate; action controls perform mutations.

Keep search, Back, Save, Edit, Delete, Filter, and row navigation familiar. Do not move a frequent command merely for visual novelty. Preserve orientation, filters, and selection across nearby steps where safe. Mobile navigation must keep the same work reachable with fewer simultaneous controls.

Keep a meaningful URL for a document, report, or filtered operational view when the route system supports it; browser Back should not unexpectedly reset the user's task. Identify the active location by text/weight/indicator as well as color. After route changes, move focus to the main content heading or equivalent region when needed for screen-reader orientation. Avoid stacking tabs, sidebars, and bottom navigation at the same hierarchy level.
