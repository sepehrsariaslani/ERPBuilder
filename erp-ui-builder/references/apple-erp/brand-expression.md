# Brand expression

Brand expression should make Hesabyar feel coherent, confident, Persian-first, and product-specific without overriding familiar ERP behavior.

## Where brand may live

Use brand expression primarily in:
- typography hierarchy;
- tone of Persian copy;
- module accent;
- icon refinement;
- empty-state voice;
- data visualization language;
- status/progress treatment;
- one or two signature interactions;
- high-level overview moments.

Keep navigation, forms, tables, lifecycle actions, and common controls familiar.

## Module identity

Finance, Sales, HR, Procurement, Manufacturing, and other modules may use a restrained module tone. Module tone:
- helps orientation;
- never becomes a separate palette/system;
- never replaces semantic success/warning/error colors;
- should not tint every surface;
- must work in light and dark themes.

## Tone

Visible Persian copy should feel:
- clear;
- calm;
- professional;
- direct;
- non-bureaucratic;
- specific about consequences.

Avoid marketing copy inside operational workflows.

## Visual personality

Prefer a small number of repeatable product signatures over styling every component:
- strong document identity;
- refined numeric typography;
- consistent section rhythm;
- restrained module accent;
- meaningful iconography;
- high-quality state transitions.

## No imitation

Do not make Hesabyar look like macOS/iOS, Stripe, Linear, Notion, or any other product. Borrow principles, not visual costumes. The output should look like a mature Hesabyar design system.
