# Dashboards

Start from `DashboardShell` and existing definitions. Name the operational question and show the few KPIs that change a decision, followed by trend, exception, comparison, and a direct drill-down. Show time range, company, filters, refresh time, and loading/error state so the numbers are interpretable.

Use charts only when they reveal a relationship better than a table. Keep units, baselines, series labels, and accessible data views. Avoid a marketing hero, decorative KPI wall, or unqualified success color. Overview density can be calm; a drill-down report can be dense.

For chart choice, interaction, keyboard access, and data alternatives, read [charts and data](charts-data.md). Distinguish an empty period, a loading period, a failed query, and a true zero. Keep a visible route from an exception or KPI to the underlying records that explain it.
