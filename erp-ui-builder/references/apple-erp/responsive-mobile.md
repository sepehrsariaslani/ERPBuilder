# Responsive and mobile

Design by available space and task, not a fixed device mockup. Desktop can use full workspace width and dense tables. On smaller screens, prioritize identity, status, next action, and a task-focused summary; move secondary detail to tabs, disclosure, or a drill-down. Keep the same business capability available.

Check RTL order, long Persian labels, safe scrolling, touch targets, on-screen keyboard overlap, and enlarged text. A mobile page is a deliberate workflow arrangement, not a scaled desktop screenshot. Validate compact and wide layouts with real content and error states.
