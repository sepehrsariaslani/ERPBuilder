# Signature elements

Hesabyar should be recognizable without turning every screen into a branded composition. Use signature elements sparingly.

## One memorable idea

Every important page may have **one memorable visual or interaction idea**, but never several competing dominant ideas.

Good signature candidates:
- a process timeline that makes operational state immediately understandable;
- a distinctive but restrained document header treatment;
- a clear exception rail;
- a compact relationship map on a 360 page;
- a high-quality KPI/variance treatment;
- a meaningful progress/status visualization;
- a uniquely fluent interaction for a core repeated task.

Bad signature candidates:
- random gradient;
- oversized decorative number;
- glass panel;
- floating blobs;
- arbitrary illustration;
- unusual navigation;
- nonstandard form controls;
- multiple different card styles.

## Signature test

A signature element must pass all of these:
1. It communicates real product information or improves a core task.
2. It can be built from or extend the existing design system.
3. It works in RTL, light/dark, compact/wide states.
4. It remains usable without motion.
5. It does not compete with the primary action.
6. It is memorable because of usefulness and craft, not novelty alone.

## Reuse

If the signature solves a recurring pattern, promote it into the Showcase/design system after proving reuse. If it is page-specific, keep it local and do not create a new canonical component solely for branding.

## Quiet surroundings

When a signature element is present:
- reduce surrounding decoration;
- keep secondary cards flatter;
- reduce competing accent colors;
- avoid multiple bold data visualizations above the fold.

Spend boldness once.
