# Document pages

Start from `DocumentPageShell`, `ProcessDocumentHeader`, `PageBreadcrumbs`, `DocumentActionDrawer`, and the closest document reference in the UI catalog. The header identifies document, business status, important exception, and next valid lifecycle action. Keep existing draft/submitted/cancelled safeguards in `SKILL.md`; do not collapse Save and Submit into an ambiguous command.

Show totals and line items near the decisions they support. Put audit trail, attachments, relations, and technical metadata in predictable sections or tabs, not duplicate summary cards. Status must explain a block and a permitted next step. Show only transitions allowed by the backend and permission state. In a long process, show completed/current/remaining stages and keep safe draft recovery.
