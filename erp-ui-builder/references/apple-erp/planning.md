# Planning

Make the plan's time horizon, capacity, dependencies, owners, exceptions, and next action visible. Use the module's existing planning surface and backend rules. Put overview, active work, and detailed constraints in separate levels without hiding blocking constraints.

Design the whole flow: choose scope → inspect constraints → change plan → see validation and impact → save/publish → recover. Direct manipulation is appropriate only when drag/resize has keyboard and explicit edit alternatives, immediate validation, and undo or safe cancellation.
